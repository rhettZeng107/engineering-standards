# ADR-033: 治理分层金字塔 + 减法纪律

- **Status**: Accepted
- **Date**: 2026-05-21
- **Decider**: 涛哥
- **Scope**: 跨项目(所有工作流 / 规则 / 记忆 / 标准 / 偏好的治理方式本身)

---

## Context(背景 / 为什么需要)

随项目积累,治理资产持续变重(2026-05-21 实测:全局 `CLAUDE.md` 231 行 + 工作区 156 行 + `rules/` 78 文件 5390 行 + 单工作区 memory 56 条)。目标是"任务一次性做对",但手段(不断**加被动文档**)边际递减且会反噬:

- **铁证**:`ADR-012` 子应用 SOP 早已存在,却没拦住 SRMV2 Contract 迁移的两个低级 bug(每菜单同页 = 漏 postMessage;网络异常 = 漏 baseURL)。**被动文档靠 AI 每次读 + 自觉执行,context 一长就被淹没 → 对 AI 失效**。
- **注意力零和**:常驻规则 100 条时,单条被遵守概率低于 10 条时。加规则求安心,实际稀释了所有规则。
- **维护债**:规则 / 记忆也是代码,会过期、矛盾;越多,人维护 + AI 加载 + 一致性对齐成本越高,拖慢协作 —— 与目标相反。

**核心误区**:把"重"当成"强"。治理强度不在量,在**是否在正确的点上强制执行**。1 个 Hook 闸 > 100 条文档规则。

---

## Decision(决策)

**一句话**:治理按**强制力分层**(金字塔),不按数量堆;新教训走**准入三闸**;定期做**减法**;用**返工率**而非覆盖度衡量。

### 1. 治理金字塔(按强制力,不按数量)

```
 顶  CLAUDE.md 活规则        ← 越来越薄(只留高频 + 无法机械化 + 必须 AI 自觉)
 中  模板 / checklist         ← 流程内嵌,启动必填(认知部分)
 底  Hook / 机制              ← 越来越厚(机器强制,承载主力)
沉淀 ADR / 工程标准文档       ← 可以厚,但按需查,不进 context
```

- **底层(Hook)是主力**:能机器强制的,绝不靠 AI 自觉。
- **顶层(CLAUDE.md)是最稀缺资源**:常驻 context、稀释注意力,只放无法下沉的。
- **沉淀(ADR)是真理源**:可以厚,但不常驻;CLAUDE.md 对已 ADR 化内容只留**一行触发 + 指针**。

### 2. 准入三闸(新教训落哪一层)

每条新教训 / 规则,依次问:

1. **能 Hook 化吗?** → 能 → 做 Hook,**不进 CLAUDE.md**
2. **是一次性 / 已固化的决策?** → 是 → 进 ADR,**不进常驻规则**
3. **高频 + 必须 AI 自觉(无法机械化)?** → 才进 CLAUDE.md

默认落点优先级:**Hook > 模板/checklist > ADR > CLAUDE.md**。CLAUDE.md 是最后手段,不是第一反应。

### 3. 减法纪律

- **已 ADR 化 + 已 Hook 化的 CLAUDE.md 段** → 精简成"一行触发 + `参见 ADR-NNN` / `由 hook X 强制`",删详述。
- **CLAUDE.md 只增不减视为警讯**:每次想加规则,先问能否下沉;hook 检测 CLAUDE.md 行数增长趋势提醒。
- **定期治理体检**(建议每完成 1-2 个项目里程碑):盘 CLAUDE.md / rules / memory,标三类 —— 可 Hook 化 / 可下沉 ADR / 可删(过期·重复·死规则)。

### 4. 衡量指标换轨

- **弃用**:"规则覆盖多全 / 资产多丰富"。
- **改用**:**返工率 / 一次性通过率**。规则越加越多但返工不降 → 证明加错了层(加了被动文档,本该加机制)。

---

## Consequences(影响)

### 正向
- 治理越来越**强**(机制化)、载体越来越**轻**(文档精简);两者解耦。
- 新教训默认机制化,不再无脑堆 CLAUDE.md;常驻 context 注意力不被稀释。
- 减法纪律防治理债累积。

### 负向 / 代价
- Hook 编写有一次性成本(但一劳永逸,优于反复踩坑 + 反复加文档)。
- 减法审计需周期投入(治理体检)。
- 部分认知性约束无法机械化,仍须靠 checklist + AI 自觉(金字塔中层兜底)。

### 影响范围
- 全局 `CLAUDE.md` / 各工作区 `CLAUDE.md` / `rules/` / memory 的精简(走治理体检减法,涛哥拍板)。
- 配套:`subapp-frontend-guard.js`(ADR-012 修订)即金字塔底层示范。

---

## Alternatives Considered

- **A. 继续堆被动文档(现状)**:边际递减 + 注意力稀释 + 维护债;ADR-012 没拦住 Contract bug 已证伪。不选。
- **B. 全靠 Hook,废文档**:认知性 / 业务判断类约束无法机械化(如 PM 视角、沟通偏好),Hook 覆盖不到。不选。
- **C. 分层金字塔 + 准入三闸 + 减法(选)**:各类约束落在最合适层,机器强制为主、文档精简为辅。涛哥 2026-05-21 拍板。
