# ADR-039: 标准任务工作流 — 业务批次与一次最终验收

- **Status**: Accepted
- **Date**: 2026-06-15
- **Decider**: 涛哥
- **Scope**: 跨项目(所有任务的通用执行骨架;统领已有正交工作流 ADR)

> 当前执行以本ADR的2026-09-07修订与全局AGENTS.md为准。下文六阶段是逻辑职责，不要求六次文档、审批、评审或工具重复执行。

## 修订（2026-09-07）— 一个业务批次、一份任务记录、一次最终验收

**授权与问题**：涛哥确认试行简化流程，并在后续协作观察效果。HC R80记录显示，隐藏字段初始化、整对象保存、兄弟入口与后端约束等问题分多轮才发现；受控页面测试也没有覆盖完整IIS/API运行。增加评审调用不能替代完整影响分析。当前没有统一耗时基线，不承诺提速比例。

**执行主线**：短需求确认 → 按业务链实现并即时验证 → 最终差异与业务证据一次验收 → 逐仓批次提交和独立状态核验。

1. 需求先明确预期行为、范围、保留约束、验收场景。代码可查事实由主会话实证；只就业务歧义、范围取舍或授权边界询问用户。已有授权不重复确认。
2. 按业务风险、契约影响和不确定性分轨，文件数/修改处数不决定流程。普通改动在一份既有任务记录中合并范围、方案、步骤与验收；短任务可用会话记录。迁移、架构和复杂长任务保留必要Spec/Plan及完整覆盖，文档之间只引用。机器汇总有需要才扩展JSON，不为形式同时维护多份相同状态。
3. 页面变更编码前按ADR-008记录紧凑依赖/字段/操作矩阵，明确隐藏保留、退出编辑、业务删除；查到真实DTO、校验、映射、持久化与兄弟消费者。尽早检查实际运行环境、账号和业务数据能否支持验收，阻塞与未验须显式记录。
4. 按可独立验收的完整业务场景实现，先跑通代表场景的进入、操作、保存、重读及保留约束，再扩展兄弟入口和剩余场景。先后顺序不削减已知总体范围；迁移完整基线和覆盖门不变。
5. 编码中做快速定向验证；最终候选只汇总一次staged diff自查与适用验证。关联未改代码属于影响范围。证据复用须记录候选标识、依赖/环境、命令、覆盖及结果；仅当前候选及相关输入未变时有效。修复重跑受影响项，共享基础、契约、依赖或运行环境变化时扩大验证；rebase带入相关变化同样失效。
6. 主会话CR负责对差异、反例与证据作综合判断，不重新执行已经有效的命令。独立Reviewer仅用户明确要求；提供影响矩阵、最终差异及证据，限定问题。发现的产品缺陷先自治修复；外部阻塞/授权边界或HIGH两轮不收敛才回报决策。强制检查未通过不得以省时放行。
7. 每仓按已验收批次合并代码、测试与文档提交并推送配置远端；纯文档任务也可独立成批。保留他人脏改、分支、pull/rebase、密钥及生产边界。最终提交号存外部执行回执或由Git查询，禁止为回填提交号递归生成收尾提交；无变更不造空提交。
8. 已逃逸缺陷固化为可复现旧错误的对应层回归；不把源码字符串检查或测试替身当作真实业务验收。HC优先保留废弃请求、异步空值、字段映射、隐藏字段保存保护及按钮/后端操作一致性案例；在原业务任务中执行，不由全局规则调整自动恢复部署。

**试行观察**：从本次规则落地后的5–10个可比业务批次取样，在既有任务记录关闭时记录一次；简单、标准、迁移及高风险任务分别比较。本次文档治理不计业务成功率。试行组仅为上述“批次与验收收敛”，期间不叠加其它全局流程实验。

| 指标 | 口径 |
|---|---|
| 首次集成验收通过率 | 第一次完整执行本批约定的集成验收集合，无产品缺陷回修而通过的批次 / 首次验收结果可判定的批次；CR PASS、局部测试绿灯不代替此值 |
| 产品返工轮数 | 集成验收开始后，由代码/业务缺陷触发的修复循环；同一循环多个检查报同一问题只记一次，保留发现阶段 |
| 环境与需求因素 | 环境/工具/测试基础设施故障与用户新增需求分别记录；未知/阻塞不计成功或失败，范围重定须保留原候选结果及原因，不能抹掉产品失败 |
| 交付耗时 | 有可靠时间戳才记录需求明确至已验收提交的elapsed时间，已知等待/环境阻塞单列；未采集填unknown，不反推模型耗时 |
| 逃逸缺陷 | 记录级别、应检出边界、发现阶段和证据；未观察到用not_observed及observedThrough，不能报告永久零缺陷 |

复盘使用[现有月度模板](../eval/templates/monthly-workflow-review.md)的试行表。旧聚合器的first-pass CR仅是历史辅助指标，不能改名充当首次集成验收率。满5个可比批次先看数据质量，最迟10个样本与涛哥共同复盘；不足样本保留观察，不为凑数制造任务或后台周期调用。质量边界放宽、覆盖下降或出现相关HIGH逃逸时先纠正受影响规则，不以速度收益抵消缺陷。规则实施完成与试行效果验证分开报告。

**官方依据**：[OpenAI最佳实践](https://learn.chatgpt.com/guides/best-practices)支持明确目标/上下文/约束/完成条件、困难任务先规划、简短AGENTS及工具验证；[子代理实践](https://learn.chatgpt.com/docs/agent-configuration/subagents)支持有界委派和注意协调成本。批次/度量细则是本地试行决策，并非官方强制模板。2026-09-07缓存manual Best practices 1788–2019、Multi-agent 2020–2457已核对。

## Context(背景 / 为什么需要)

工作流各环节早有正交 ADR(① 调研=016 / ② 实证=015 / ③ 判断=018 / ④ 处理=017 / ⑤ 检查=036+008 / ⑥ 汇报=018),但**缺一条把它们串成端到端的可见主线** —— 新会话 / AI / 涛哥无单一总览,易跳步:**跳调研 = 重复造轮子;跳实证 = 臆测;跳检查 = 黑箱/误判完成**。

**实践验证**:2026-06-15 一次治理 session(迁移知识收敛 + 35 ADR 聚类审计 + 全仓索引)完整走了这条主线 —— 先**调研**现有 6 处迁移资产 + 历史 ADR-033/playbook → **实证**读全文 + 跑 37-agent 审计 → **判断**(实证反转「ADR 不该合并」+ 批判「同主题≠合并」)→ **处理**(批次落盘)→ **检查**(CR audit 工具 + 修 MED-1 + 实证 `local=remote`,**抓回了一次 commit 乱码导致的"误判已 push"事故**)→ **汇报**(标 commit + 完结清单)。其中 ⑤ 检查环节正是它抓回了事故,印证"检查不可省"。

**同模式先例**:迁移轨用 [legacy-migration-playbook §0](../standards/legacy-migration-playbook.md) 主线串 ADR-014/028;本 ADR 是通用任务版。

## Decision(决策本身)

确立 **6 阶段标准任务工作流主线**,每阶段**编排已有 ADR(不复制其内容)**,含闭环回退:

| 阶段 | 做什么 | 锚(已有 ADR / 机制) |
|---|---|---|
| **① 调研** | 先扫历史 / 现有资产；项目地图仅在能缩短发现时按需使用,不重复造轮子 | ADR-016 + ADR-025 |
| **② 实证** | 拿真证据(`file:line` / 命令 / DB),分实证 vs 假设;上游报告 trust-but-verify | ADR-015 + ADR-030 A3 |
| **③ 判断** | 基于事实给方案 + 批判视角(识真问题,非迎合表面)+ 按授权档汇报 | ADR-018 + ADR-019 |
| **④ 处理** | 按方案落盘,批次自治不打断,跨契约本体先锁 | ADR-017 + ADR-037 + ADR-003 |
| **⑤ 检查** | CR 门禁 + E2E 核对 + 自产复核(连 commit/push 都实证 `local=remote`) | ADR-036 + ADR-008 |
| **⑥ 汇报** | 标来源,完结一次性报告,触线自报 | ADR-018 + ADR-015 |

- **闭环**:⑤ 检查出问题 → 回 ④ 处理;② 实证反转既定前提 → 停回 ③ 升档报涛哥(不带错认知前进)。
- **档位压缩**:简单任务(Tier 1 小改)可压缩(④ 直接做 + ⑤ 自检),但 **① 调研 / ② 实证 / ⑥ 汇报 三步不可跳**(跳 = 重复造轮子 / 臆测 / 黑箱)。

## 修订(2026-08-06)— 标准轨完整合同先行，禁止 MVP/演示切片替代完整交付

**问题**:标准轨若只从当前页面或少量样例反推需求，容易把用户提供的多份表格、截图、旧系统能力和跨角色流程压缩成少字段、单 happy path 的演示页；随后又把“页面能打开”误报为模块完成，导致契约、实现和验收三次返工。

**决策**:

1. 标准轨在处理前必须把明确需求、用户提供资料和现有代码/DB/API 的实证合并为受影响业务边界内的完整 contract lock，覆盖角色、场景、字段最大并集、操作、状态、异常、集成、菜单/鉴权和验收用例；不得由 agent 擅自用 MVP、最小可行性或演示级字段/场景缩减已知范围。涛哥明确批准的原型/阶段范围可执行，但不得冒充整体完成。
2. 允许按 Phase/批次实施，但分批只改变顺序，不改变完整合同。单批任务可直接复用 spec 验收表，多批任务才建独立 coverage ledger；每个合同项须有稳定 ID、批次、验收、证据和 `covered/pending/blocked/approved-defer` 状态。外部依赖缺失默认 `blocked`，仅涛哥明确批准后转 `approved-defer`。本批承诺项全覆盖后可标 `batch-complete`；执行中模块标 `in-progress`，批次关闭但仍有剩余项标 `partial`，零剩余项才标 `complete`。涛哥重定基线后，`approved-defer` 项须带决策/证据迁入父级或 backlog ledger，禁止静默删除。
3. 外部契约未取得时，不依赖该契约的内部能力须完整实现；依赖外部报文的字段、状态、映射和写请求禁止猜测。已有或合同约定的用户入口须实现禁用态、待接入/错误反馈和禁止假成功边界；无 UI 的任务须返回稳定能力状态/错误码并留审计证据。
4. 本修订约束业务范围完整性，不授权过度设计、无关扩建或新增不必要抽象；实现仍遵循复用优先和最小必要代码改动。

### 工具输出可信度铁律(2026-06-15 翻车补强,hook `core-git-push-verify` 强制)

> 翻车事实:`git push` 实际失败(仍 `[ahead]`),但因复杂命令(`2>&1` / `&&echo` / `|tail`)输出被污染,Claude 用先验补全「push 成功」连续 3 次误报。代码/文件未损(操作非破坏性),但状态误报会侵蚀信任、且同机制若用于破坏性操作前置判断会真破坏。

- **b. 完成类断言只认独立验证**:「已 commit / 已 push / 已同步」必须基于独立命令(`git status -sb` 无 `[ahead]` / `rev-parse HEAD == @{u}`),**不得基于 commit/push 命令自身输出**。
- **c. 禁先验补全**:绝不复述工具输出里未逐字可见的值(hash / 数字 / 成功行);输出被截断 / 污染 / 标 malformed → 只能说「输出不可靠,重验」,严禁用训练先验补 git 该输出什么。
- **a. 最简命令**:git 状态变更用单命令、英文 message,勿拼接 `2>&1` / `&& echo` / `| tail`(实证为污染源)。机器兜底 = PostToolUse hook `core-git-push-verify` 每次 push/commit 后独立回显真实 `git status -sb`。

## Consequences(影响)

### 正向
- 端到端可见主线;串联正交 ADR 不重复;新会话 / AI 有统一执行骨架。
- 防跳步 —— 尤其防"误判完成"(本 session ⑤ 检查环节即抓回 commit 丢失事故)。

### 负向 / 代价
- 简单任务别教条走全套(用压缩档兜底)。
- 主线是导航非新规则,各环节仍以对应 ADR 为准(避免与下层重复)。

### 影响范围
- 全局 `CLAUDE.md` 顶部加精炼主线表 + 指针(ADR-009 cheatsheet 风格)。
- `decisions/README` 归「治理元方法」簇。

## Alternatives Considered

- **A. 新建大 ADR 复制各环节细则** — 否:制造与 015/016/017/018/036/008 重复,违反 2026-06-15 聚类审计确认的「正交不合并」精神。
- **B. 纯写全局 CLAUDE.md 详述** — 否:违反 ADR-009(CLAUDE.md 薄)+ ADR-033(准入三闸:详细下沉 ADR)。
- **C. 编排主线 ADR + CLAUDE.md 精炼指针(选)** — 串联不复制,符合治理金字塔。
