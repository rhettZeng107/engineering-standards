# ADR-027: 踩坑复盘 → 分层沉淀闭环机制

- **Status**: Accepted
- **Date**: 2026-05-17
- **Decider**: 涛哥
- **Scope**: 跨项目

---

## Context(背景 / 为什么需要决策)

### 触发场景

2026-05-17「MDM 主数据分发模块」spec / 编码全流程多处踩坑(discuss 未读项目地图、上游 agent 误判被采信、EF 实体字段类型错配、EF 实体幻影列)。涛哥反馈:**踩过的坑必须复盘总结,沉淀成工程标准 / ADR / Hook / memory** —— 才能提高协作效率、提高交付质量。

### 当前状态实证

- 踩坑后的沉淀**不系统**:有时记 memory、有时落 ADR、多数靠自觉;无「坑」的触发定义,无强制闭环。
- 本次多个坑若早有复盘沉淀本可避免 —— 如「整行复制前 EF 实体未对照 DB schema 核验」是可复用教训,踩了两次(`ParentId` 幻影列 + `prop9/10/11` 类型错配)。

### 决策不做的代价

坑反复踩;经验散落不沉淀;协作效率与交付质量持续受同类问题拖累。

---

## Decision(决策本身)

**一句话**:建立「踩坑复盘 → 分层沉淀」闭环机制 —— 所有坑即时复盘、按性质分层沉淀到 memory / ADR / Hook / 工程标准 / 项目地图;以 `docs/post-mortem/` 为坑账本,**复盘不落地即未完成**。

**详细**:

1. **坑触发(任一即触发复盘)**:涛哥纠正 / 推翻基线;返工(CR CRITICAL/HIGH 回修、E2E 暴露 bug);实证反转;上游 agent 误判被采信。
2. **复盘动作**:坑发生当下轻量记一笔 —— 根因 / 本该怎样 / 沉淀去向;不打断批次。
3. **分层沉淀(类比 ADR-002 决策分层)**:

   | 坑性质 | 沉淀载体 |
   |---|---|
   | 一次性 / 项目特化 / 协作偏好 | memory `feedback_*` |
   | 横向 ≥2 场景 / 跨项目 / 推翻规则 / 长期基线 | ADR |
   | 模式固定、可脚本判定拦截 | Hook |
   | 流程 / 清单 / 规范 | 工程标准(engineering-standards) |
   | 平台机制认知盲区 | 项目地图 `MECHANISMS.md` |

4. **载体**:`docs/post-mortem/` 作「坑账本」,每坑一条复盘记录,**必须写明「已沉淀到 X」**;只复盘不落地 = 未完成。
5. **节奏**:单坑即时轻量记;批次 / spec 完结汇总统一沉淀;完结报告附「踩坑 + 沉淀」段。

## Consequences(影响 / 副作用)

### 正向

- 经验系统沉淀,坑不重踩;同类问题被前置拦截。
- 沉淀有明确分层,不再散落、不再靠自觉。

### 负向 / 代价

- 每个坑多一道复盘 + 沉淀开销(轻量,可控)。

### 影响范围

- 影响所有项目所有批次;`docs/post-mortem/` 升级为强制坑账本。
- 影响完结报告格式(新增「踩坑 + 沉淀」段)。
- 关联 ADR-021(Hook 沉淀承接)、ADR-026(平台机制盲区沉淀去向)。

## Alternatives Considered(其他选项 + 为什么没选)

### A. 维持现状(靠自觉记 memory)

- 不选原因:本次已证不系统、漏沉淀、坑重踩。

### B. 只复盘不强制沉淀

- 不选原因:复盘不落地等于没做,无法前置拦截下一次。
