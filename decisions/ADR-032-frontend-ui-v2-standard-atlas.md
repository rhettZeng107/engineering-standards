# ADR-032: 公司前端 UI V2 统一工程标准(Atlas)

- **Status**: Accepted
- **Date**: 2026-05-21
- **Decider**: 涛哥
- **Scope**: 跨项目(公司全线前端工程标准:SYSV2 = SYS.3 / BP / AuditPortal / MDM,以及 SRM / MES / WMS / EAM / TPM 计划)

> **2026-09-22 修订**：以下“Context”记录 2026-05 的问题背景；现行决策与执行细则以本文“Decision”及 [`frontend-ui-v2-standard.md`](../standards/frontend-ui-v2-standard.md) 为准。MDM 页面视觉效果已获涛哥确认；业务保存回读、权限反例与其他子应用仍各自验收。
>
> **2026-09-23 修订**：列表字段筛选固定为工具栏按钮触发的默认关闭弹层，以 SYSV2 MDM `VFilterProTable` 为实现参考；点击筛选不得在页面流中插入面板。服务范围等共享字段结构的多行集合统一使用共享表头表格及可编辑表格模式，禁止重复卡片或分块表单。

## Context(背景 / 为什么需要决策)

### 触发场景

2026-05-21 BP 业务门户子应用 UI 重构讨论。涛哥定调:现行前端 UI 强制标准(`engineering-standards/standards/frontend-ui-standard.md` = antd 5 + pro-components + ListPage 四段式 + AutoHeightProTable + 工具栏三图标)**观感偏 antd 默认、模板感重**,要求重构一套**更现代、更高级、面向操作水平不一最终用户、导航清晰**的统一 UI 标准 V2,且**作为公司跨项目工程标准**。

### 当前状态实证

| # | 现状 | 实证锚点 |
|---|---|---|
| 1 | V1 UI 标准 = antd 默认观感,强约束四段式 / AutoHeightProTable / 三图标 | `engineering-standards/standards/frontend-ui-standard.md`(注:**非** ADR-023,ADR-023 是 i18n/Auth/hostMap/web.config 基建标准) |
| 2 | 多字段录入靠抽屉「一拉到底」,操作员体验差 | 涛哥反馈 + MDM `supplier/suppliersubmajor.jsx` 多 tab 长表单 |
| 3 | 各前端无统一「门户 shell + 业务页」设计语言,视觉碎片化 | BP `BpLayout.jsx`(深蓝 Sider)vs MDM 子应用各自样式 |

### 不做决策的代价

各应用 UI 各自演进,迁移改造(SRM/MES/WMS/EAM/TPM)各搬各的观感,无法形成公司统一产品形象;操作员跨应用学习成本高。

---

## Decision(决策本身)

**一句话**：UI V2 是所有前端页面编码的统一工程标准；`frontend-ui-standard.md` 保留基础技术细则，不能作为降低页面要求的替代基线。页面用同一视觉语言支持浅色、深色和跟随系统，产品品牌色按 token 映射。

### 1. 与基础技术标准的关系

> 页面范式和验收真理源为 [`frontend-ui-v2-standard.md`](../standards/frontend-ui-v2-standard.md)；[`frontend-ui-standard.md`](../standards/frontend-ui-standard.md) 和 [`react-ui-guidelines.md`](../standards/react-ui-guidelines.md) 补充 antd / ProTable 及列表交互细则。ADR-023 是 i18n / Auth401 / hostMap / web.config 基建标准，与 UI 页面标准正交。

- 新增、修改、重构、迁移的页面都在同批按 V2 的页面类型实现与验收；未触及的存量页保留原状，进入编码批次即不再适用旧 V1 例外。
- 跨文档条款冲突时以 V2 为准；基础文档只补充组件和交互实现，不提供“快速交付”或嵌入页面豁免。

### 2. V2 "Atlas" 设计语言定义

| 维度 | 现行约束 |
|---|---|
| 字体 | 采用项目已有中文系统字栈与可用本地字体；无外网字体请求，数字/编号按需使用等宽或 tabular 数字 |
| 主题与色彩 | 画布、工作面、导航、表头、浮层、文字及状态使用浅/深 token；青绿主动作、信息蓝、琥珀风险、红色危险/阻断和中性灰按业务语义映射，产品品牌色可保留 |
| 令牌化 | CSS 变量与 antd `ConfigProvider` 同步明暗；宿主将实际主题传给已打开的子应用，不重载业务页 |
| 层级 | 紧凑标题、薄边界和可读表格密度；状态同时显示文字与色点/图形，列表不堆叠装饰卡片 |

### 3. 页面范式与关键组件标准

- **门户 Shell 与工作台**：侧栏、菜单选中底纹、顶栏、页签和工作台随实际主题切换；BP 作为子应用主题传递的宿主，具体菜单与卡片内容按 BP 业务契约。
- **列表**：单行标题/主动作；结果数与筛选、刷新、密度、列设置四工具同排；字段筛选默认收进工具栏触发的弹层，条件数可见且可清除，打开不得推挤表格；少数低基数枚举可保留表头快捷筛选。表头紧凑，行内操作按普通/危险语义区分。
- **同构多行记录**：服务范围、证照、关系、途经点、费率阶梯、参数明细和业务单据明细只要共享字段结构，就以一套表头、一行一记录的只读/可编辑表格呈现；新增可创建新行或打开当前行短弹窗，浏览层不得改成重复卡片或分块表单。
- **新增、编辑、详情与流程**：多字段业务在 Main 内独立路由页，按业务分区或步骤组织，支持深链、刷新恢复、保存回读及未保存提示；短事务保留 Modal。
- **参数配置**：独立路由、配置范围、薄边界分区、影响预览、修改原因与统一保存；明暗及窄屏保持可读。
- **空/加载/错误与上传**：业务三态明确；附件与导入使用统一 Dragger，提供进度、错误及回显。

### 4. 落地硬约束(plan 编码阶段强制验收,2026-05-21 涛哥两点)

> 效果图(mockup)阶段静态示意即可;**spec 确认 + plan 落盘编码时**必须满足:

- **① 字段要"活"**:按真实业务字段实装、填真实数据、**禁占位符空字段**冒充;字段集以源系统实证为准(如 MDM 供应商 / 物料 / 客户字段,见对应 spec 字段依据),不臆造、不简配。
- **② 自适应**:响应式适配多分辨率 + 浏览器缩放(125%/150%),**无重影、无错位叠加**;`fixed`/`absolute`/`sticky` 布局须在窄屏与缩放下健壮。

### 5. 同一视觉语言与主题

V2 统一页面结构、状态语义和验收要求。浅色、深色、跟随系统是用户可选择的显示模式；具体品牌色由产品 token 映射，菜单可见性仍由授权决定。客户定制品牌方案须另有产品契约，不从主题切换推导。

### 6. 技术选型边界

设计语言可供不同前端技术栈采用；当前 [`frontend-ui-v2-standard.md`](../standards/frontend-ui-v2-standard.md) 给出 React 18、antd 5 与 pro-components 的具体落地要求。其他技术栈须在项目中给出等价组件与真实 UI 证据。

## Alternatives(替代方案)

| 方案 | 否决理由 |
|---|---|
| 维持 V1(ADR-023)仅微调 | 解决不了「模板感 + 抽屉一拉到底」核心诉求 |
| 各应用各自设计 | 视觉碎片化,违背公司统一产品形象目标 |
| 直接采购成熟组件库套皮 | 仍是「别人的脸」,且企业字段密度 / 中文场景适配差 |

---

## Consequences(影响)

- **正面**:公司前端统一现代观感;操作员跨应用一致体验;迁移改造(SRM/MES…)有统一目标基线。
- **代价**：各应用逐页适配明暗 token、列表交互和独立业务路由，业务保存与权限仍需独立验收。
- **影响范围 / 回链**：[`frontend-ui-v2-standard.md`](../standards/frontend-ui-v2-standard.md) 为现行标准；基础技术细则、迁移手册及 BP 子应用接入手册均回链 V2。
- **视觉对照**：[列表明暗示例](../references/ui-v2-theme-examples/list.html)与[参数页明暗示例](../references/ui-v2-theme-examples/settings.html)。
