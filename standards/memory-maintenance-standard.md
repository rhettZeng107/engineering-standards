# Memory 维护标准

> 修订 2026-09-09：偏好保留、规则索引化、历史证据保留。适用的是维护方法，不授权改写生成式 Memory。当前政策按运行时及 AGENTS 指令链裁决，详 [Harness 标准](provider-neutral-ai-coding-harness-standard.md) 与 ADR-044。

## 三类内容与生命周期

| 内容 | 保留方式 | 不应承担 |
|---|---|---|
| 稳定用户偏好 | 简短、去重、标适用范围；用户修订后替换旧偏好 | 重复完整全局规则 |
| 已固化规则 | 主题、适用项目、当前权威文件路径 | 另存一套政策正文、固定模型路由或交付节奏 |
| 已完成任务证据 | 日期、项目、来源/候选、结果、当时例外，标历史 | 当前任务的下一动作或永久豁免 |

当前执行状态只认项目唯一 progress/任务记录；接续指针不复制计划。保留尚未完成、暂停、禁止项和批准的项目例外，不为压缩而抹去证据。

## 写入与生成边界

- 用户明确要求更新后，先识别资产归属和当前运行时允许的入口；授权不覆盖运行时限制。
- Codex 管理的 `MEMORY.md`、`memory_summary.md`、rollout 与生成索引不是普通项目文档；本流程不直接覆盖、合并、删除或修改其状态库。
- 若运行时仅允许提交 ad-hoc 更新输入，写清目标条目、保留项、替换内容与依据；不要反复提交同一请求来冒充处理。
- 人工维护的项目召回索引仅在明确授权且位置/归属已确认时编辑；不得把 Codex 目录中的文件仅凭名称当作人工资产。
- 初始化默认不创建 Memory，也不要求每个项目存在 `curated-memory/MEMORY.md`。可选 [索引模板](../templates/MEMORY.md.template) 不是自动注入配置。
- 不存凭据；不把项目地址、账号或运行状态复制到团队发行包。

## 去重方法

1. 合并同义偏好，保留适用范围和有效例外；优先用清楚的业务语言，API/枚举/文件名不随意改写。
2. 已进入 AGENTS/ADR/standard 的政策正文换成短索引，但相关历史证据不因政策变化删除。
3. 历史一次性指令注明所属任务和当时条件，不能作为下一批默认行为。
4. 路径存在不等于事实仍有效：检查链接目标和当前项目来源；无目标时标失效，不强制读取空路径。
5. 文件数量/行数仅作观察线索，不是自动删除门槛；不为凑阈值拆成更多文件或删未解决事项。

## 如何确认完成

分开报告以下状态，不能互相替代：

- **输入已提交**：更新要求已落到允许的入口；不是正文已更新。
- **正文已验证**：读取实际生成/维护结果，确认目标重复项已合并、政策已索引化、历史与项目例外保留、链接有效；修改时间或 hash 变化本身不够。
- **后续召回已验证**：在实际后续会话检查召回内容，没有把历史例外当当前规则；未验证则如实注明。

官方将本地 Memory 视为后台生成状态，会跳过活跃/过短会话，额度条件也可能阻止生成。`/memories` 管理当前聊天的使用/生成开关，不是本文承诺的强制合并入口；重登、退出或提交输入不保证立即生效。遇到未合并，查受支持的生成配置/日志并报告未知，不盲目重建或重复写入。
