# Frontend UI V2（Atlas）标准

> 状态：正式。React 18、antd 5 与 `@ant-design/pro-components` 项目按本文直接实施；其他前端技术栈提供等价实现与验收证据。
> 本文只规定 V2 的强制边界；列表交互细则直接引用
> [`frontend-ui-standard.md`](frontend-ui-standard.md) 与
> [`react-ui-guidelines.md`](react-ui-guidelines.md)，不在三份文档中重复维护。
> 组件参考片段：`references/v2-components/`；页面规则以本文与引用的列表细则为准，产品 token 由实际项目维护。
> 2026-09-22 视觉验收基线：SYSV2 的 BP 门户与 MDM 试点已在 10.31 完成明暗主题、紧凑列表及参数页的真实入口核对；涛哥确认 MDM 页面效果达到预期。此结论只覆盖页面视觉与交互方向，业务写入回读、权限反例及未保存导航仍按项目矩阵独立验收。

## 1. 适用原则

- 本标准是所有前端页面编码的强制基线，不区分简单轨、标准轨、迁移轨或其他任务类型。新增、修改、重构和迁移页面必须在同一交付批次按 V2 落盘并验收；不得因改动小、沿用旧页面、只改字段/按钮/接口或计划后续美化而豁免。
- 页面必须先判定为列表页、独立业务路由页、短事务 Modal 或看板/报表，再套对应范式；不得用 V2 页头、颜色或卡片替代完整页面范式。
- 业务字段、按钮、校验、请求和保存契约不得因布局升级被删减。真实保存、持久化、回显和失败路径仍按项目验收标准执行。

## 2. Token 与基础组件

- 入口统一引入 `v2-tokens.css`，并将品牌色、语义色、圆角、画布、文字和字体映射到 antd `ConfigProvider`；页面不得硬编码主题色。
- 新增或修改的页面须使用同一套语义 token 覆盖浅色与深色：画布、容器、浮层、表头、边框、主次文字、焦点、链接及状态色均随主题变化。产品可保留自己的品牌主色；业务状态色按含义选用，不把品牌色当成全部成功色。支持主题切换的宿主须让已打开的子应用同步实际主题，未接入的子应用不得计为全站双主题完成。
- 宿主侧栏、菜单分组、搜索、账户区、顶栏与首页工作台须跟随实际主题；浅色模式使用浅色导航工作面与深色文字，深色模式使用深色导航工作面与浅色文字。工作台欢迎区、卡片、状态和应用图标均使用主题 token。当前页签对应的左侧菜单须持续显示选中底纹，点击其他菜单或切回已打开页签时同步切换；品牌色用于选中、焦点和动作，不把侧栏固定为深蓝色。
- 主动作、状态与风险操作按下表分别判断。`新增`只表示创建，不能自动推断为安全；例如「加入黑名单」虽有“加入”动词，仍是限制供应商资格的危险操作。操作列不得用无业务含义的多色按钮。

| 角色 | 适用行为或状态 | 浅色 / 深色表达 | 交互要求 |
|---|---|---|---|
| 主动作 | 新增普通档案、查询、保存、确认配置 | 青绿实心按钮；深色使用亮青绿底配深字 | 同一区域只突出主要下一步；禁用态保留原因 |
| 普通动作 | 查看、编辑、导出、返回、刷新 | 中性按钮或青绿文字链接 | 操作列用文字说明动作，图标按钮提供名称和焦点 |
| 需关注 | 待复核、临期、缺资料、尚未保存 | 琥珀文字、底色或提示边；不作为默认“提交”按钮色 | 写出风险及下一步，不能只靠颜色 |
| 危险动作 | 删除、作废、驳回、移出受控范围、加入黑名单等限制性变更 | 红色 `danger` 按钮或链接；深色红底配深字 | 标明作用对象、二次确认，成功后刷新或回读 |
| 结果状态 | 可用/通过、处理中、风险、阻断、历史中性 | 青绿、信息蓝、琥珀、红、灰的文字＋浅/深底色 | 不同业务维度分列，状态同时显示文字与点或图形 |

色值由产品 token 与 antd `ConfigProvider` 提供；浅色参考青绿 `#0b726b`、深表头 `#174653`，深色参考亮青绿 `#56c4b7`、表头 `#34464a`。表头文字与排序、筛选图形在两种主题下都须可读；危险、成功、风险色不按字面动词套用。正文与底色至少 4.5:1，重要图形和控件边界至少 3:1；悬停、选中和禁用状态分别检查。
- 业务页复用 `SectionCard`、`StepAnchorNav`、`EditableRecordTable`（既有单据可保留 `InlineDetailTable` 别名）和 `V2States`；禁止自造同职能组件或用空卡片冒充业务分区。

设计效果对照：列表页[白天](../references/ui-v2-theme-examples/list-light.png)／[夜晚](../references/ui-v2-theme-examples/list-dark.png)，参数页[白天](../references/ui-v2-theme-examples/settings-light.png)／[夜晚](../references/ui-v2-theme-examples/settings-dark.png)。HTML 可切换主题并查看窄屏排布；示例数据不代表任何业务契约。

视觉试点实现参考：MDM [`VFilterProTable`](../../SYSV2/AI.REACT.MDM.1/src/v2/components/VFilterProTable.jsx)、[`VFilterProTable.css`](../../SYSV2/AI.REACT.MDM.1/src/v2/components/VFilterProTable.css)、[`VToolbar`](../../SYSV2/AI.REACT.MDM.1/src/v2/components/VToolbar.jsx)、[`VPageHeader`](../../SYSV2/AI.REACT.MDM.1/src/v2/components/VPageHeader.jsx) 与[参数页](../../SYSV2/AI.REACT.MDM.1/src/setting/index.jsx)；BP [主题上下文](../../SYSV2/AI.REACT.SYS.BusinessPortal/src/context/ThemeContext.jsx)和[工作台](../../SYSV2/AI.REACT.SYS.BusinessPortal/src/views/Workbench/index.jsx)。这些文件展示已落地的交互，子应用按自己的数据、权限和路由契约实现，不把 MDM 组件当成跨仓依赖。

## 3. 列表页（强制）

列表页的定义、布局和交互以
[`frontend-ui-standard.md`](frontend-ui-standard.md) 与
[`react-ui-guidelines.md`](react-ui-guidelines.md) 为唯一细则来源，并至少满足：

1. 使用 `ListPage`：标题与主操作、紧凑结果工具栏、表格与分页；字段筛选默认收在工具栏“筛选”按钮触发的弹层内。不得用多层 `Card`、常驻搜索条、点击后插入页面文档流的筛选块或页面级 `Spin` 占据列表顶部。
2. 主表使用 `ProTable` 或项目自包含的 `AutoHeightProTable`。查询条件以字段级、带标签的控件呈现，优先复用 `columns` 的搜索声明；`search.labelWidth="auto"`。桌面默认使用定位到筛选按钮右下方的 `Popover`/等价非路由弹层，窄屏可使用受控全宽弹层或底部弹层，但不得改为常驻或推挤表格。弹层提供重置、查询和清除全部；查询提交后关闭并保留已应用条件，取消/按 Esc 不得误提交且关闭后焦点返回触发按钮。
3. 工具栏依次保留筛选、刷新、密度、列设置四个小图标；筛选显示已应用条件数并可一键清除。`toolBarRender={() => []}`，不得设为 `false`；列设置须支持显隐和拖拽排序，宽表按业务需要支持固定列。
4. 每列声明稳定 `width`；编号、时间、状态等常用列保持一致口径。操作列固定在右侧、宽度统一，查看/编辑/删除及状态动作的顺序和危险色遵循 React 列表标准。
5. 新增、导入、批量操作等页面级动作放在 `ListPage.Title.extra`；不得挤入 ProTable 内部工具栏。空、错、加载使用 `V2States`，接口异常不得伪装成空数据。
6. 列表视觉顺序为「单行标题/主操作 → 同排结果数与四工具 → 表头/数据/分页」；筛选弹层覆盖在工作面上，不属于该纵向结构。单层面包屑若与标题同名，只显示标题；多层面包屑只保留有导航意义的上级。四工具桌面统一 32×32px 边框盒，触控视口不小于 44×44px，图形约 14×14px 且居中；筛选弹层按字段数在桌面排两列、窄屏排一列，限制高度并内部滚动，不遮挡触发按钮、关键操作或溢出视口。触发按钮须有 `aria-expanded`、可访问名称、提示和可见键盘焦点；弹层须支持 Esc、点击外部关闭及关闭后焦点恢复。视觉示例见[明暗列表页](../references/ui-v2-theme-examples/list.html)。
7. 表头仅对状态、类型等少数低基数枚举列保留快捷筛选；文本、日期、范围及跨列条件在面板内。表头与面板使用同一条件状态、同一服务端全集过滤与分页，不能只过滤当前页；清除全部后回到未筛选结果。无有效查询字段的局部表不造空面板。业务页签不作为筛选条件时保留在列表外。
8. 表格表头使用深青绿工作层和高对比文字，常规单行表头高度约 38px、字号约 12px；排序、固定列、筛选图形的普通、悬停与选中状态一起适配；行内普通编辑用青绿文字，危险操作用红色文字并确认。具体品牌色可映射，不得把浅色表头或状态色硬编码到深色主题。

普通 antd `Table` 只适用于看板内部摘要表、表单明细表或无分页/无 CRUD 工具栏的非列表型局部表格；不得用于规避列表页标准。

## 4. 新增、编辑、详情与流程页（强制）

- 原 Drawer 或宽 Modal 中的新增、编辑、详情、主从和流程业务，统一改为 Main/门户框架内的子应用路由独立页。列表通过 `navigate(route)` 进入，页面按 route id 重新取数，支持刷新和深链。
- 独立页使用画布背景，利用 Main 可用宽度，左右安全边距 5–15px；顶部包含面包屑、标题、说明和右上角操作区，主体按业务分组使用 `SectionCard`，长页面按需使用 `StepAnchorNav`。
- 新增页右上角为 `[返回][保存]`；编辑页为 `[返回][删除][保存]`；详情页为 `[返回]+已授权业务动作`。返回采用 `navigate(-1)` 或明确来源路由；不得同时提供同义“返回”和“关闭”。
- 保存成功返回来源列表并触发刷新；未保存返回、并发冲突、加载错误和无权限必须有明确反馈。不得只依赖 Drawer 内存或 `location.state` 维持页面数据。
- 确认、提示、导入以及无明细且不超过 10 个字段的短事务可保留普通 Modal；不得把覆盖式全屏 Modal 当作独立页。字段可选性按当前界面语言标为“选填”等本地化文案，不直接暴露 `optional` 等开发术语。
- 单页面参数配置属于独立业务路由页。按配置范围、平面薄边界的业务分区、影响预览、修改原因及统一保存组织；不以多层圆角卡片堆砌。长页面显示未保存状态和当前影响，未保存用琥珀、已保存用青绿、保存失败用红色文字与反馈；保存失败保留输入并定位错误。实际字段、权限、生效时点与历史快照由所属业务契约决定。明暗布局示例见[参数页](../references/ui-v2-theme-examples/settings.html)。

## 5. 同构多行记录与可编辑表格（强制）

- 只要一个集合的多条记录共享同一字段结构并需要横向比较、批量浏览或连续维护，就必须以一套共享表头和一行一记录的语义表格呈现。该规则覆盖服务范围、证照、人员/车辆关系、途经点、装载兼容关系、费率阶梯、参数明细，以及询价单、采购申请、采购订单、发货计划、发货单等 `1:N` 同构明细；不以当前只有一条记录为豁免。
- 查看态使用只读 `Table`/等价语义表格；新增和编辑优先复用 `EditableRecordTable`，既有物料单据可继续使用其 `InlineDetailTable` 别名。一行对应一条业务记录，共享字段名只在表头出现一次；“新增记录”创建新行或打开当前行的短编辑弹窗，查看、编辑、复制、删除等行级动作集中在最右操作列。
- 禁止把同构记录渲染成纵向堆叠卡片、分块列表或 `Form.List + Card/div/Flex` 的重复字段组，尤其不得逐条重复“服务范围 1/2/3”、字段标签、删除区和说明。只有记录之间本身字段结构不同、以图像/地图/时间轴为主要识别对象，或单条记录包含无法安全行内编辑的大型异构子流程时，才可使用非表格呈现，并在任务记录说明原因；即使采用单行编辑弹窗，集合浏览层仍保留共享表头表格。
- 每行使用稳定业务 ID；新增未保存行使用稳定临时 key。新增、删除、复制、排序和批量导入按业务契约启用，不由组件猜测。删除既有记录须确认作用对象；并发、重复键、日期交叉、区间重叠和关联占用等失败定位到具体行/单元格，并保留其他行输入。
- 条件字段可使用动态列、单行展开或“当前选中行”的唯一辅助编辑区；不得一次展开 N 套大型表单。列宽、固定关键列/操作列和横向滚动由字段集决定，不得为消除滚动删减字段。窄屏继续保留表格语义，可横向滚动或用弹窗编辑当前行，不得退回卡片堆叠。
- 详情页与新增/编辑页保持相同字段语义、列顺序和行粒度。保存验收使用至少两条真实记录证明持久化，并在编辑页或详情页重新读取，核对数量、稳定标识、关键字段、顺序及适用反例；只验证一条、接口 200、表格渲染或前端内存值不能证明多行契约完成。
- 业务主单与明细默认作为一次保存处理；除非契约明确支持并逐行展示部分成功，否则任一行失败不得反馈整体成功。物料选择仍须保留契约要求的 ID、编码和名称；附件与导入分别复用 `FileUploader`、`ImportModal`。

## 6. 上传与导入（强制）

- 所有附件上传统一使用 `FileUploader`，所有 Excel/批量导入统一使用 `ImportModal`；底层必须是 antd `Upload.Dragger`，同时支持拖拽和点选。
- 禁止裸 `<input type="file">`、只点选的 plain `<Upload>` 或页面自造上传器。组件必须覆盖文件类型、大小、数量、上传状态、删除、下载/预览和错误反馈。
- `FileUploader` 按场景使用 `action`、`defer` 或 `base64` 数据流；受控值必须在顶层保留 `fileId`。`ImportModal` 必须提供模板、上传、解析/预览、逐行错误和成功后的刷新语义。

## 7. 验收门

- 静态检查：列表页具有 `ListPage`、工具栏触发且默认关闭的字段筛选弹层、四工具、条件数/清除入口和统一操作列，页面流中不存在常驻或点击后插入的字段筛选块；业务 Drawer/宽 Modal 为独立路由；所有同构多行集合使用共享表头表格和统一操作列，不存在按记录重复渲染的卡片/整组表单；上传入口只使用统一 Dragger 组件。
- 行为检查：从真实门户菜单进入；筛选弹层的打开、查询、重置、清除、Esc/外部关闭与焦点恢复，以及分页/列设置、CRUD、返回、刷新恢复、上传成功和失败均可操作；可编辑集合覆盖至少两行的添加、编辑、删除及适用的导入/附件，并完成保存回读与行级反例；关键列使用真实数据且不为空或 `-`。
- 视觉检查：桌面及适用移动端在 100%、125%、150% 缩放下无重叠、截断和无效大留白；固定列、横向滚动和操作区可用。列表四工具在真实浏览器中分别核对桌面 32×32px、触控视口至少 44×44px 的边框盒、约 14×14px 的居中图形及原有功能；筛选默认收起且不留空白，打开后为不推挤表格的弹层并保持在视口内，表头单行约 38px，快捷筛选或排序图形不挤压字段标题。
- 主题检查：浅色、深色及跟随系统的实际画面均核对宿主侧栏、菜单选中态、搜索、账户区、首页工作台、画布、表格、表单、弹窗、通知和状态徽章；浅色导航须为浅色工作面，深色导航须为深色工作面。切换不清除查询或未保存输入，不刷新已打开的子应用页签。正文与背景对比度至少 4.5:1，状态文字、图标、边界至少 3:1；颜色以外仍有文字或图形语义。
- 工程检查：build/test 通过，外网字体请求为零，主题 token 无页面级硬编码。任一适用项未覆盖时，页面不得标记为 UI V2 完成。

## 8. 工作流要求

- AI UI 能力按职责分层：`frontend-design`负责页面创作与设计方向，`frontend-quality-gate`负责基于源码、渲染结果和项目规范的证据化审查；`impeccable`仅作为显式调用的补充工具，用于确定性检测或可信本地环境的可选 Live Mode。不得用任一技能的审美偏好覆盖本标准、项目设计系统和业务契约，也不得把检测无告警当作真实 UI、可访问性或业务验收通过。
- `impeccable`默认关闭隐式触发、自动 Hook 和遥测；确定性检测先作为人工审查证据，不直接成为 CI 阻断条件。Live Mode 只允许在用户明确要求后操作可信本地源码与开发服务器，不得为其放宽生产 CSP、浏览器安全或部署边界。
- 任一任务轨只要涉及页面编码，编码前必须登记受影响页面及 `pageType`，编码中实施对应 V2 条款，批次验收提供页面级静态证据和真实 UI 行为证据。任一适用项未通过，页面与批次不得标记完成。
- 后续每个接入门户的子应用按其实际页面矩阵逐页实施本文与引用的列表标准：在子应用内使用主题 token 渲染明暗两套页面，从真实门户入口核对主题同步、列表工具和状态语义；只修改门户外壳或共享样式，不能代替子应用页面代码及业务行为的验收。MDM 的视觉评审结论允许复用设计方向，不替代其他应用的页面矩阵、业务写入回读和独立评审。
- 日常页面变更按[页面变更轻量验收标准](page-change-acceptance-standard.md)执行“最终 staged diff 本机主门 + exact SHA 部署后 CI 二次门”；按影响面验收不等于省略入口、保存回读或兄弟消费者，也不要求每次跑全菜单。
- 项目可接入 [`ui-v2-contract-guard.mjs`](../templates/hooks/ui-v2-contract-guard.mjs) 对 staged 前端文件执行确定性检查：阻止已知内联筛选模式、`toolBarRender={false}` 和 `Form.List` 重复卡片/块。项目可通过配置补充自己的共享组件名；例外必须写带原因的窄范围指令并由任务记录审查。机械 Hook 不能理解业务同构性、保存回读、可访问性或真实布局，不得替代本节静态与真实 UI 验收。
- 迁移项目额外把“源功能等价”和“目标 UI V2 符合性”作为同一迁移单元的两个并列合同：源页面清单保证不漏业务，本文及其列表细则保证目标形态。两者同批编码、同批提交、同批 E2E；任何一项未通过，迁移状态只能是 `partial`、`pending` 或 `blocked`，不得记为 `complete`。
